# Decisions

Choices made while implementing [docs/QUOTEDESK_PLAN.md](docs/QUOTEDESK_PLAN.md) where the plan
left room or the simplest option needed stating. Newest milestone at the bottom.

## M0 — Scaffold

| # | Decision | Why |
|---|---|---|
| D1 | The app is called **QuoteDesk** everywhere: repo, window title, PyInstaller target (`QuoteDesk.exe`). The plan file is `docs/QUOTEDESK_PLAN.md`. | Owner's request. |
| D2 | The plan supersedes `docs/superpowers/specs/2026-09-03-quotation-system-design.md` (Next.js/Postgres, multi-user). The old spec is kept for history only. | The new plan is single-user, local, Python. |
| D3 | Sample files live in `backend/tests/fixtures/` only. `samples/` is not kept as a second copy. | Avoids committing ~11 MB of binaries twice. |
| D4 | Python ≥ 3.11 is supported (CI uses 3.12, dev machine has 3.13). | The plan names 3.12; nothing used needs more than 3.11. |
| D5 | Migrations and seeding run **inside the app on startup** (`app/migrate.py`), not as a separate step in the start scripts. | One code path for the seller, dev, Docker and tests. `alembic upgrade head` still works by hand from `backend/`. |
| D6 | The API key is stored in `data/.env` (chmod 600), not in a repo-root `.env`. | Everything user-specific lives in `data/`, which is git-ignored and backed up as one folder. |
| D7 | Money columns use a `Money` type stored as **TEXT** (Decimal quantized to 4 dp). Floats are rejected at bind time. The API returns money as JSON strings. | SQLite's NUMERIC affinity silently converts to REAL. TEXT keeps exact decimals. |
| D8 | Product search uses FTS5 with the **trigram** tokenizer. Terms under 3 characters fall back to `LIKE` on the FTS table. | Product names are unsegmented Chinese, so the default tokenizer can't match `海力士` inside `沃存海力士颗粒`. Trigram can't match 2-character terms like `镁光`, so those use `LIKE`. |
| D9 | The FTS index is maintained in Python (`services/search.py`) on every product write, not with SQL triggers. | It indexes the brand's names and the attributes text, which live in other tables or JSON. |
| D10 | Default LLM model is `claude-sonnet-5-5` (editable in Settings). | The plan says "claude-sonnet-4-5 or newer"; this is the current Sonnet. |
| D11 | The dev `docker-compose.yml` runs uvicorn on `0.0.0.0` *inside* the container but publishes ports on host `127.0.0.1` only. `python -m app` (what the seller runs) is hard-wired to `127.0.0.1`. | A container must listen on its own interface to be reachable at all; the host binding keeps the no-LAN rule. |
| D12 | The startup backup runs **before** migrations, so a failed migration can be rolled back by restoring the newest backup. | Cheap insurance. |
| D13 | Frontend uses TypeScript `tsc --noEmit` + Vite (no project references), ESLint flat config, Prettier. `npm run lint` also runs `scripts/check-i18n.mjs`, which fails if `en.json` and `zh.json` differ in keys or a literal `t('key')` is missing. | Keeps "every string through i18n, both catalogs" enforced in CI. |
| D14 | Initial UI language is Chinese. The top-bar switch saves `ui_language` to `settings.json`, which wins on load. | The seller works mostly in Chinese; the server copy follows the data folder. |

## M1 — Catalog

| # | Decision | Why |
|---|---|---|
| D15 | Attribute schema field types: `text, number, int, capacity, frequency, form_factor, interface, brand, bool`, plus optional `unit` and `options` (suggested values, not enforced). | The normalizer needs to know how to canonicalize each value. Source data varies too much to enforce enums. |
| D16 | New attribute type **`brand`** for vendor-like attributes (`chip_vendor` 颗粒, `wafer_vendor`, `nand_vendor`). They normalize through brand aliases, so `海力士` and `SK hynix` fingerprint the same. | Plan §3.4 requires brand aliases to resolve in both languages; chip vendors are brands too. |
| D17 | If a product has **no** identifying attribute filled in, its normalized `name_zh` stands in for the attribute part of the fingerprint. | Otherwise every attribute-less manual item in a category with the same (empty) brand would collide. |
| D18 | Brand cells like `江波龙（Airdisk）` are resolved by trying the whole string, then the part outside the brackets, then the part inside. | Matches how the source sheets write brands. |
| D19 | `brand_aliases.alias_key` (normalized, whitespace removed) is **unique**: one spelling resolves to exactly one brand. | Prevents ambiguous resolution; the API returns `brand.alias_taken` naming the other brand. |
| D20 | Remark rules are a `note_rules` table (`pattern, field, kind=set|qty|text, value`). The first matching rule wins per field. | Extensible from Settings later (M6) without code changes. |
| D21 | Max-order rule is `(?<!库存)可接单?\s*([\d.]+)\s*(K\|pcs)?`, so `可接13K` (no 单) also counts, but `库存可接12K` stays a from-stock quantity. | The RAM-module screenshot uses `可接13K,预付30%`. |
| D22 | `供应良好` stores the remark in `supply_note`. Plan §1.4 says "supply = good", but the schema has only `supply_note`. `大众市场` sets a new `market` column. | Keeps the original wording (e.g. `Q4供应良好`) visible. |
| D23 | Manual price edits are `POST /products/{id}/prices` (an endpoint the plan didn't list). Each edit appends a `price_history` row with `import_id = NULL`, `source_ref = "manual"`, and marks it current for its tier. | The plan requires inline price edits to create manual history rows. |
| D24 | `DELETE /products/{id}` hard-deletes the product and its price history. "Deactivate" is a status change (`inactive`) offered next to it in the UI. Once quotes exist (M4), lines keep their snapshot and `product_id` becomes NULL. | Simple, and quotes never depend on the live product. |
| D25 | Merge keeps the target's current prices; the dropped product's rows become history (still current only for a tier the target had no price in). The dropped ERP codes go to `erp_code_alt`. Empty fields on the target (MPN, English name, brand, descriptions) are filled from the dropped product. | "Keep" means keep. |
| D26 | Changing a category's identifying attributes does **not** rewrite existing fingerprints. Each product is re-fingerprinted on its next save or import. | Avoids a bulk rewrite that could suddenly create collisions. A "re-fingerprint all" action can come with M6 if needed. |
| D27 | Product list sort by price casts the TEXT money column to REAL **for ordering only**. Arithmetic never uses it. | Lexical order would put `9.5` after `10`. |
| D28 | The price chart in the UI converts prices to numbers only to compute plot coordinates; every displayed amount is formatted from the decimal string (BigInt-based `formatDecimal`). | The no-float rule applies to anything a user reads. |

## M2 — Import (xlsx via AI)

| # | Decision | Why |
|---|---|---|
| D29 | Hidden sheets are listed (with a "hidden" tag) but never pre-selected; visible sheets that look like price tables are. | The sample workbooks hide old or archived tables (`DB小板汇总 (2)`, `Sheet3`…). The plan's golden sheets such as `DDR颗粒参考价` are hidden and must be ticked by hand. |
| D30 | When a sheet has both an RMB price and its own USD column, the USD column is the price. The RMB amount and rate are kept as `amount_original` / `fx_rate`. QuoteDesk converts RMB itself only when no USD column exists. | `domestic WIFI`'s USD column is RMB ÷ 1.13 ÷ 6.7175: it removes 13% VAT. Converting 14.85 ÷ 6.7175 ourselves would give $2.21 instead of the sheet's $1.96. |
| D31 | Only the current (right-most) price per tier is imported. Older price columns are not back-filled into the history. | Their dates are fuzzy (`5月`, unnamed `参考价`); history builds from one import to the next. |
| D32 | `.xls` is refused with a "save as .xlsx" message. `.csv` is accepted (UTF-8 or GB18030). | openpyxl cannot read `.xls`; adding `xlrd` for a format no sample uses isn't worth it. |
| D33 | Extraction uses `claude-sonnet-5-5` (the plan names Sonnet; editable in Settings) with structured outputs (`output_config.format` JSON schema), effort `medium`, streaming, the server-side refusal fallback (`fallbacks: "default"`), and a cached system prompt (rules, category schemas, brand list). Up to 4 chunks of 60 rows run at once. A chunk that hits `max_tokens` is split in half and retried. | Valid JSON every time; cache hits on every chunk after the first; long sheets don't time out. |
| D34 | Model amounts are parsed with `json.loads(parse_float=Decimal)`, so no extracted price is ever a float. A price of `0` in the source means "no price". | Money rule; `domestic WIFI` writes 0 when the RMB price is empty. |
| D35 | Rows with a model confidence below 0.6 get a "low confidence" note in review. | Draws the eye without blocking. |
| D36 | Several rows resolving to the same product in one import: the last row (sheet order, then row order) is applied, earlier ones are skipped with a "duplicate" note. | Same rule as "last upload wins". `DB小板汇总` repeats `XN35` three times. |
| D37 | Fuzzy match = Dice similarity of character trigrams of the normalized Chinese name ≥ 0.85, same category, only when no ERP code, part number or fingerprint matched. The seller must pick a candidate or "create new" before commit. | Plan §3.4 step 4, kept deterministic and dependency-free. |
| D38 | Updating an existing product merges attributes (new values win, other keys kept), never blanks the English name or part number, adds new ERP codes to `erp_code_alt`, and never changes a manual `inactive` status. Every other status and flag follows the latest import's remarks. | The newest list is the truth, but the seller's own edits survive. |
| D39 | Commit is all-or-nothing. If any row fails, nothing is applied and the failing rows carry a "failed" note. | A half-applied price list is worse than none. |
| D40 | Only the most recent committed import can be reverted. Revert deletes this import's price rows and restores the previous current rows. Products it created are deleted only if no other price row (manual or other import) exists. Fields it changed are restored from a snapshot. Brands it created are deleted if unused. | Undoing an older import under a newer one would have no well-defined result. |
| D41 | Unknown brands are created at commit with `needs_review`. For `中文（English）` cells the English part becomes the canonical name and both parts become aliases. | Plan §3.5; matches how brands appear in the sheets. |
| D42 | Catalog and import screens show cost prices with 2 to 4 decimals (`$ 1.9563`, `$ 3.10`); sell prices (quotes, M4) use 2. | Cheap components are quoted to the tenth of a cent. |
| D43 | The §4.3 golden tests come in two layers. Offline tests replay recorded model output for real rows of both workbooks through the full pipeline. `tests/test_golden_live.py` runs the real model on the same sheets, only with `QUOTEDESK_LIVE=1` and an API key. | CI stays free and deterministic; the live check is one command away. |
| D44 | **Two AI providers**, chosen in Settings: Anthropic Claude (default `claude-sonnet-5-5`) or Google Gemini (default `gemini-3.8-flash`, the current stable Flash). Each has its own key in `data/.env` (`ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) and its own model field. Both use the same prompt, the same JSON schema and the same Decimal parsing. Gemini runs with thinking level `medium` and relies on its implicit prompt caching. Its thinking tokens are counted as output tokens. | Owner's request to use a Google key. Keeping Claude available costs one class and lets the seller compare the two on real sheets (the live golden tests run once per key given). |

## M3 — Import (screenshots + PDF)

| # | Decision | Why |
|---|---|---|
| D45 | An import is **one spreadsheet**, or **any mix of screenshots and PDFs**. Each image and each PDF page becomes a selectable source in the same wizard as sheets (`sheets[].kind` = `sheet` / `image` / `pdf_page`). Mixing a spreadsheet with other files is refused (`import.one_spreadsheet`). | Plan §4.1: several screenshots selected together are one import. Reusing the sheet list keeps hints, progress, filters and review unchanged. |
| D46 | A PDF page with a text layer is sent as **numbered text lines plus the rendered page (150 dpi)**. A page with almost no text (< 20 characters) counts as scanned and is sent as an image only. | The plan says text first, vision as fallback. The UPS offer's text layer interleaves wrapped descriptions with the price line, so the image gives the model the table structure, and the text gives exact values and a line number to cite. One page image costs little. |
| D47 | A screenshot row's `source_row` is its position in the table, counted from the top. A PDF row's is the line number of its price. The review drawer shows the whole image (or page) next to the row, plus the cited text line for PDFs. | Images have no row numbers or cell coordinates. The plan's fallback is "just the image". |
| D48 | Images are sent as uploaded unless they exceed 2576 px on the long edge or 3.5 MB. Larger ones are downscaled and re-encoded as JPEG. Gemini gets them at `MEDIA_RESOLUTION_HIGH`. | Sonnet 5.5 reads up to 2576 px. Dense tables of small digits (the CPU list) need full resolution. |
| D49 | A screenshot or page can't be split, so it gets a 64K output cap (spreadsheet chunks keep 32K). A unit that still overflows fails with a clear error; the others continue. | The CPU screenshot has ~90 rows with two price tiers each, which is the largest seen. |
| D50 | Number attributes accept the field's unit, with an optional `k` prefix: `28W`, `14KG`, `24AH`, `10KVA` (= 10000 VA). They are stored as bare numbers. Any other suffix is still invalid. | The prompt asks for source text with units. Without this, every CPU row (`TDP 28W`) was a Problem row. |
| D51 | Notes printed above or below a table (the SSD screenshot's red `注：ink方案…`) are not rows. The model reports them once, in the first row's issues, and the review shows them as an AI note. | Keeps the information visible without inventing a product. |
| D52 | When a quotation's product name is generic (`Battery cabinet`), the model takes the model from the description (`C6`, `C8`), so the two cabinets stay two products. | Otherwise the identifying `model` collides and the second cabinet would be skipped as a duplicate. |
| D53 | **Groq** is a third provider (`GROQ_API_KEY`, default model `qwen/qwen3.8-27b`). It is the only Groq model with both vision and strict JSON-schema decoding. It is called through the official `groq` SDK, with reasoning `low` and hidden. Its answers are capped at 16,384 tokens, so oversized spreadsheet chunks split as usual. Groq has no prompt-cache marker, so the system prompt is resent with every chunk. | Owner's request. On 2026-10-04, the free tier allowed 8,000 tokens per minute (input + output) on every model, plus 1,000 output tokens per minute on Qwen. A 6-row screenshot needs about 2,300 output tokens. Real imports need Groq's paid Dev Tier. |
| D54 | **An ERP code outranks the attribute fingerprint.** Rows or products with the same identifying specifications but different ERP codes are different products: the second one's fingerprint is qualified by its ERP code. In one import, each ERP code keeps its own last row. A row without a code joins the first code's product, and the winning row keeps the codes of the rows it replaces. A fingerprint or fuzzy match never lands on a product with a different code. If two codes both match one existing product that has no code, the second row is skipped with a warning. Creating or editing a product by hand follows the same rule. | Seen with Groq on `DB小板汇总`: the model gave `XN35` without its SKU, and three boards with three ERP codes (and prices) collapsed into one. ERP codes are unique per part (plan §1.1), so they decide identity whenever both sides have one. |
| D55 | Products record **when and by which import they were added** (`created_import_id`, next to `created_at`). The product list has a sortable "Added" column (local date and time, plus the import's file name, or "Entered by hand"), and the product page also shows the last import that updated it. Migration 0003 fills the column for earlier imports from each import row's commit record. It adds the column with a plain `ALTER TABLE … ADD COLUMN` instead of rebuilding the table, and migrations now run with SQLite foreign keys off. | Owner's request. With foreign keys enforced, an Alembic batch migration that rebuilds a table drops it first, which cascade-deletes child rows (price history, import rows). SQLite's guidance is to disable foreign keys during schema changes. |

## M4 — Customers, quotes, proforma invoices

| # | Decision | Why |
|---|---|---|
| D56 | Offer numbers are `WKZ` + `YYYYMMDD` + `-NN`, counted per day (`WKZ20261004-01`), with the prefix taken from Settings. **New revision** keeps the number and prints `… R2`. **Duplicate** takes a new number. | Plan A6. The samples show `WKZ20260811` without a sequence because only one offer went out that day. |
| D57 | Only a **draft** quote can change. Its status can always change, and a sent or accepted quote is adjusted through a new revision. | What the customer received stays reproducible. |
| D58 | Line price = `round_half_up(cost × (1 + margin/100), rounding)`. The margin comes from the first of: the line's own margin, the customer's, the category's, then Settings. Typing a unit price overrides that and shows the margin it carries. Typing a margin, or "back to cost × margin", hands the price back to the formula. Line total = qty × unit price, rounded to cents. A discount is either a percentage or an amount, never both. | Plan §5.2, all in Decimal. |
| D59 | A product line copies these fields when it is added: the name (English for an English document when the product has one), the description (in the document language, falling back to the imported `description` attribute, then to a summary of the attributes), the model (`model_no`, or the `model` attribute, or the MPN), the material and the photos. Later catalog changes never alter the quote. A changed price shows a **price changed** warning with a **Use current price** action. | Plan §3.9: lines are snapshots. |
| D60 | Line warnings are computed live from the product as it is now: status (discontinued, stock only, no supply, inactive), confirm before order, needs validation, price on request, no stock (stock = 0), quantity above the maximum order, price older than *N* days (Settings, default 30), price changed since the line was added, no price, product deleted. | Plan §5.2 warnings icon. |
| D61 | Description lines are edited as text, one spec per line. A line starting with `!` prints in red. A **name in red** checkbox covers the UPS sample's red model names. | The fastest way to type 20 spec lines, and it matches both samples. |
| D62 | PDFs use US Letter paper like the samples and embed Noto Sans SC (static Regular/Bold instances of Google's OFL font, under `backend/app/assets/fonts`). A table row never splits across pages. Text that can't fit its cell shrinks, like Excel's shrink to fit, instead of breaking mid-word. List tables are always summed (owner decision). A list line without specs prints its name in the Description column. | Matching the samples. CJK glyphs need an embedded font. Instancing the variable font took about 20 s per document. |
| D63 | **Placeholder decision:** the quote header's `Email:` is the **customer contact's** email. It is filled from the customer and can be edited per quote. | The 2-in-1 sample prints it next to the customer's contact. The owner may still decide it should be the seller's email. |
| D64 | Proforma invoices are created only from an **accepted** quote, from the lines the seller ticks. The number is `pi_prefix` + `YYYYMMDD`, with `-02`, `-03` … for further invoices that day; the default prefix is `PI` (the sample's `ANZX` belongs to another company). An issued PI never changes: **New revision** makes a draft `…-R2`, and an issued PI can be cancelled. FOC prints as `x% FOC` under the description at no charge. Freight is added to the total. The four terms come from Settings templates, where `{trade_term}` is replaced by the quote's trade term. | Plan §5.4. |
| D65 | Bank details, seller contact and signature are Settings fields, left empty until the owner fills them. A PI keeps a copy of the seller contact as it was when the PI was created. | The owner asked to keep them as placeholders. |
| D66 | Photos, the logo and the signature are stored under `data/images/`. Documents embed a copy at most 1000 px wide. Removing a photo from a product only unlinks it, and the file stays for quotes that print it. | Phone photos would otherwise make every PDF several MB. |
| D67 | The Excel exports mirror the PDF layouts. Line and section totals are live formulas. Red spec lines use rich text, and the photos sit inside the Photo cell. | Plan §5.3. The seller can keep editing the file. |
| D68 | Customer codes are stored in upper case and are unique. Deleting a customer keeps the copy of their details in existing quotes. Configuration lines (`kind = config`) arrive with M5. | |
| D69 | Every quote has two versions. The **customer version** (the existing PDF/Excel) never shows cost. The **internal version** (`export.pdf?internal=true`, `export.xlsx?internal=true`, file names ending `_INTERNAL`) lists each line's unit cost, margin, total cost, total price and profit. It also gives the total cost, quote total, profit after the discount and the margin on cost. Lines without a cost are left out of cost and profit, and the document says how many. A red banner on both files says not to send them. The internal Excel uses formulas, so margins can be tried there. | Owner request: one copy to keep, one to send. A separate document is harder to send by mistake than a hidden column. |
| D70 | **Combined products** (plan §5.2 "config" lines, brought forward from M5). A quote line of kind `config` holds its parts in `quote_lines.components`, a JSON list. Each part is a snapshot of `{product_id, name, qty per unit, cost_usd, condition new/used, price_date}`. The plan calls this JSON field `breakdown`. The line's cost is always Σ qty × cost of its parts. The customer documents print it as one row: the name, the parts as description lines (`2*…` for several, `(New)`/`(Used)` or `(全新)`/`(二手)` for the condition), the photo and one price. The internal version lists the parts with their costs under the line. **Combine** turns two or more lines of one table into such a line; its quantity is the GCD of their quantities. **Split** reverses that. The description follows the parts until the seller edits it; **Rebuild description** regenerates it. Part warnings (price changed, no price, status, old price) name the part, and *Use current price* refreshes every part. Saved, reusable configurations (the Configurations page) remain M5. | Owner request: the customer sees the finished product and its price, and the seller keeps the parts and costs. |
| D71 | Configurations follow plan §3.10 with two simplifications. There is no `role` column, since the order of the parts is the printed order. Photos are an `image_ids` JSON list on the configuration instead of rows in `product_images`. Each part is also one printed description line (`name`, `emphasis` = red, `condition` new/used). A spec with no cost (keyboard layout, ports, CE/ROHS) is a typed part with cost 0. A catalog part always takes the product's current price and never stores one. `saved_cost` is the cost at the last save: the page warns when catalog prices have moved it, and **Accept new cost** (any save) clears the warning. | The 2-in-1 sample's description is exactly the list of parts and specs. |
| D72 | **Insert configuration** creates a combined line (D70) at today's prices. Its name is `name_zh` for Chinese quotes, and model no., material and photos are copied. The configuration's `base_margin_pct` becomes the line's margin. The line records `configuration_id` for **Where used**. Deleting a configuration keeps the quote lines, since they are snapshots. A combined line built in a quote can be saved as a configuration; the line is then linked to it. | Plan §5.2 "Add configuration". |
| D73 | Dashboard widgets (plan §6): the last committed import (new / updated / unchanged), open quotes (draft + sent) with their total value, price changes over 20% in the last import (each against the product's previous price for the same tier), lines of open quotes whose product or part changed price, stopped being sold or was deleted, and active products whose price is older than `price_age_warning_days`. The four catalog counters moved to the Products page at the owner's request. | |
| D74 | **Manual column mapping** (plan §4 fallback). Works on spreadsheets only, one sheet at a time: the seller gives the title row, the name column(s), the price, the optional fields (ERP code, MPN, brand, English name, stock, demand, stock after orders, remarks, platform), the category's attributes, the currency and the CNY rate. Each row becomes the same dict the AI returns, so review and commit are shared. Mapping a sheet again replaces its rows, and other sheets keep theirs. It is offered on every sheet, not only without a key, and shows as "Columns mapped by hand" (`llm_model = manual`). The dialog suggests a mapping from the column titles. A price that isn't a positive number is kept as the row's no-price reason. | |
| D75 | **Backups** in Settings → Backups. A database backup uses SQLite's online backup API and is named `manual-…`; startup copies are named `app-…`. A full backup is a zip of app.db, `images/`, `imports/` and `settings.json`, never `.env`, and the newest 10 are kept. Restoring first saves the current database as `before-restore-…`, then migrates the restored database. A restore is refused while an import is extracting. Uploaded backups must be a SQLite file or a zip holding `app.db`, and zip paths are checked. Retention (`backup_retention`) is editable on that tab. | Plan §9. Moving to a new laptop is upload + restore. |
| D76 | **Settings polish.** `pdf_show_cost_breakdown` was removed: the internal version (D69) shows costs and the customer documents never do. Unit-price decimals (`rounding`) can now be edited. Note rules can be edited (create, edit, enable, delete), with a regex check and a required number group for quantity rules. The default rules are seeded only into an empty table, so a deleted rule stays deleted. | Owner: the customer never sees costs. |
| D77 | **Desktop build** (plan §9): a PyInstaller one-folder build, `backend/packaging/quotedesk.spec`, producing `QuoteDesk/QuoteDesk.exe`. Read-only files (interface, migrations, fonts) come from the bundle. `data/` is created next to the executable, so an update replaces the folder and keeps `data/`. Started by double-click, it opens the browser and keeps a console window that tells how to stop. PyInstaller cannot cross-compile: `.github/workflows/desktop.yml` builds and smoke-tests the Windows folder on `windows-latest` (manual run or `v*` tag) and attaches it as an artifact. The executable is not code-signed, so SmartScreen asks once (documented). | Plan A8, §9. |
| D78 | **Chinese text review.** All 735 strings were reviewed against the English. Terms are now uniform: 产品库, 报价单, 形式发票, 整机配置, 组合产品, 部件, 利润率, 确认入库, 疑似重复项, ERP料号, 规格参数; errors read 未找到… / …为必填项. Seller guides: `docs/INSTALL.md` and `docs/INSTALL.zh-CN.md`, with screenshots in both languages. | Plan M6. |
